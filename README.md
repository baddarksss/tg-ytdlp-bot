# 🤖 tg-ytdlp-bot — نسخهٔ بهینه‌شده برای Railway

ربات تلگرام دانلود ویدیو/عکس/صدا (یوتیوب، اینستاگرام، تیک‌تاک، توییتر، فیس‌بوک، VK، پینترست و…).

این نسخه برای **Railway** آماده شده: **همهٔ تنظیمات با متغیر محیطی (Variables)** انجام می‌شود؛ هیچ فایلی را لازم نیست ویرایش کنی.

> روی VPS با داکر هم کار می‌کند (فایل `Dockerfile.vps` + `docker-compose.yml`).

---

## ✅ چیزهایی که قبل از شروع لازم داری

| مورد | از کجا |
|---|---|
| توکن ربات | [@BotFather](https://t.me/BotFather) → `/newbot` |
| `API_ID` و `API_HASH` | [my.telegram.org](https://my.telegram.org) → API development tools |
| آیدی عددی خودت | [@userinfobot](https://t.me/userinfobot) |
| کانال لاگ (۲ عدد کافی است) | یک کانال بساز، ربات را ادمین کن؛ آیدی عددی کانال را بگذار (`-100…`) |
| اکانت Railway | [railway.app](https://railway.app) |

> ⚠️ ربات را در کانال‌های لاگ **ادمین** کن، وگرنه ارسال لاگ خطا می‌دهد.

## 🚀 راه‌اندازی گام‌به‌گام (۵ دقیقه)

### گام ۱ — پروژه را در Railway بساز
1. در Railway → **New Project** → **Deploy from GitHub repo** → همین ریپو را انتخاب کن.
2. اگر برنچ خواست: `main`. (Railway خودش `Dockerfile` را می‌سازد و `railway.json` را می‌خواند.)
3. صبر کن بیلد تمام شود (~۵ تا ۱۰ دقیقه بار اول). اگر بیلد خطا داد، برو سراغ بخش «عیب‌یابی» پایین.

### گام ۲ — Volume بساز (مهم‌ترین گام)
سرویس → **Settings** → **Volumes** → **New Volume** → **Mount path: `/data`**

بدون این کار، **کاربران، کوکی‌ها و کش** با هر دیپلوی پاک می‌شوند و هر بار باید کوکی را دوباره بدهی.

### گام ۳ — متغیرها را ست کن
سرویس → **Variables** → **Raw Editor** → این را کپی کن و مقدارها را عوض کن:

```env
BOT_TOKEN=123456789:AAxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
API_ID=12345678
API_HASH=0123456789abcdef0123456789abcdef

BOT_NAME_FOR_USERS=my_bot_username
ADMIN=123456789
LOGS_ID=-1001234567890
LOG_EXCEPTION=-1001234567890
TZ=Asia/Tehran
```

سپس **Deploy** بزن (یا خودش redeploy می‌کند).

### گام ۴ — لاگ را نگاه کن
اگر همه‌چیز درست باشد، در **Deploy Logs** می‌بینی:

```
📎 ...
🐍 Python : Python 3.11.x
🎬 ffmpeg : ffmpeg version ...
🟩 Node   : v22.x
📦 DATA_DIR : /data (پایدار)
🚀 ربات اجرا شد (PID=…)
```

اگر متغیر اجباری جا افتاده باشد، ربات با پیام واضح بالا نمی‌آید:

```
❌ این متغیرها ست نشده‌اند: BOT_TOKEN API_ID API_HASH
```

### گام ۵ — اولین تست
در تلگرام ربات را باز کن → `/start` → یک لینک یوتیوب بفرست.
اگر ویدیو آمد، تمام است. برای کوکی و کیفیت یوتیوب → بخش‌های بعدی.

### گام ۶ (اختیاری) — پورت/دامنه برای مانیتورینگ
سرویس → **Settings** → **Networking** → **Generate Domain**.
بعد از آن آدرس `https://دامنه/health` وضعیت ربات را JSON می‌دهد (`botAlive`, فضای آزاد دیسک، …).
می‌توانی همین آدرس را در **Healthcheck** یا یک سرویس UptimeRobot بگذاری.
اگر پورت نمی‌خواهی، هیچ کاری نکن — ربات بدون پورت هم کامل کار می‌کند.

## 🔑 متغیرها

### ۱) اجباری — بدون این‌ها ربات بالا نمی‌آید

| متغیر | توضیح | نمونه |
|---|---|---|
| `BOT_TOKEN` | توکن ربات از @BotFather | `123456789:AA…` |
| `API_ID` | از my.telegram.org | `12345678` |
| `API_HASH` | از my.telegram.org | `0123456789abcdef…` |

### ۲) مهم — برای کارکرد کامل

| متغیر | توضیح | نمونه |
|---|---|---|
| `BOT_NAME_FOR_USERS` | نام ربات در دیتابیس (یوزرنیم بدون `@`) | `my_dl_bot` |
| `ADMIN` | آیدی عددی ادمین‌ها (با کاما) | `123456789,987654321` |
| `LOGS_ID` | کانال لاگ اصلی | `-1001234567890` |
| `LOG_EXCEPTION` | کانال خطاها | `-1001234567890` |
| `BOT_NAME` | نام داخلی (اختیاری) | `tgytdlp-bot` |
| `ADMIN_USERNAME` | یوزرنیم ادمین | `@my_username` |
| `ADMIN_GROUP` | گروه‌هایی که محدودیت ندارند | `-1001234567890` |
| `ALLOWED_GROUP` | گروه‌های مجاز | `-1001234567890` |
| `ALLOWED_USERS` | اگر پر باشد، فقط این آیدی‌ها در چت خصوصی | `123,456` |
| `TZ` | منطقهٔ زمانی (برای زمان‌بندی‌ها) | `Asia/Tehran` |

### ۳) کانال‌ها و عضویت اجباری (اختیاری)

| متغیر | توضیح |
|---|---|
| `LOGS_VIDEO_ID` / `LOGS_NSFW_ID` / `LOGS_IMG_ID` / `LOGS_PAID_ID` | کانال لاگ تفکیکی (اگر نگذاری، از `LOGS_ID`/`LOG_EXCEPTION` استفاده می‌شود) |
| `COPY_CHANNEL_ID` | کانال‌های مقصدِ **کپیِ تمیزِ فیلم** (`-100…` یا `@username`؛ چند‌تا با کاما). خالی/`0` = خاموش. ربات باید آن‌جا ادمین باشد |
| `COPY_CHANNEL_ASK` | `1` (پیش‌فرض) = بعد از هر آپلود، زیرِ فیلم دکمهٔ کانال‌ها می‌آید و خودت انتخاب می‌کنی؛ `0` = بی‌سؤال در اولین کانال کپی شود |
| `RAILWAY_API_TOKEN` | اختیاری — توکنِ API ریلوی؛ اگر بگذاری، دکمهٔ «☁️ ذخیره در Variables» و `CHANNEL_AUTOSYNC` کار می‌کنند (توکن فقط داخلِ خودِ سرویس می‌ماند) |
| `CHANNEL_AUTOSYNC` | `1` = هر اضافه/حذفِ کانال داخلِ ربات، خودکار در `COPY_CHANNEL_ID` نوشته شود (پیش‌فرض `0`) |
| `SUBSCRIBE_CHANNEL` | آیدی کانال عضویت اجباری — `0` یعنی غیرفعال |
| `SUBSCRIBE_CHANNEL_URL` | لینک دعوت همان کانال |
| `CHANNEL_GUARD_SESSION_STRING` | فقط برای اسکنر ChannelGuard (نیاز به سشن یوزر دارد) |
| `MINIAPP_URL` | آدرس مینی‌اپ (اگر داری) |
| `STAR_RECEIVER` | آیدی دریافت‌کنندهٔ استارز (برای محتوای پولی) |

#### 📢 کپیِ فیلم در کانال (چند‌کاناله)

ربات می‌تواند هر فیلمی که برایت آپلود می‌کند را در کانال‌های خودت هم بگذارد:

1. ربات را در کانال **ادمین** کن (با اجازهٔ «Post messages»).
2. کانال را اضافه کن — دو راه:
   - داخل خود ربات: دستور **`/channels`** → دکمهٔ **➕ افزودن کانال** → آیدی را **ریپلای** کن
     (مثال `-1001263727544` یا `@mychannel`). ربات خودش چک می‌کند در آن کانال ادمین است یا نه.
   - یا در Railway → Variables: `COPY_CHANNEL_ID=-100111…,-100222…` (چند‌تا با کاما).
3. بعد از هر آپلود، **زیر خودِ فیلم** یک دکمه برای هر کانال می‌آید؛ هر کدام را بزنی همان
   فیلم با **همان کپشن** به‌صورت **پستِ تازه** (بدون «Forwarded from») در آن کانال می‌رود
   و دکمهٔ آن کانال ✅ می‌شود. دکمهٔ ➕ همان‌جا اجازهٔ افزودنِ کانالِ جدید را می‌دهد و
   ✖️ دکمه‌ها را برمی‌دارد.
4. `/channels` هر وقت خواستی: فهرستِ کانال‌ها + اینکه ربات کجا ادمین است، حذفِ کانال،
   دکمهٔ «🔄 بررسیِ ادمین‌بودن» و دو دکمهٔ **بکاپ**:
   - **💾 بکاپِ کانال‌ها**: یک خطِ آمادهٔ `COPY_CHANNEL_ID=…` می‌فرستد (و به‌صورت فایل
     `COPY_CHANNEL_ID.txt` هم). همان یک خط را در Railway → Variables بگذار؛ دفعهٔ بعد
     که سرویس از نو بالا آمد، کانال‌ها **خودشان** برمی‌گردند و لازم نیست دستی اضافه کنی.
   - **☁️ ذخیره در Variables**: خودِ ربات همان مقدار را از API ریلوی می‌نویسد
     (نیاز به `RAILWAY_API_TOKEN` + آیدی‌های پروژه/محیط/سرویس). سرویس یک بار ری‌استارت می‌شود.

> کانال‌هایی که از `COPY_CHANNEL_ID` می‌آیند با 🔒 نشان داده می‌شوند (فقط از Variables
> حذف می‌شوند). کانال‌هایی که داخلِ ربات اضافه می‌کنی در فایل `channels.json` پوشهٔ داده
> ذخیره می‌شوند. **بدونِ Volume، این فایل با هر دیپلوی پاک می‌شود** — پس یا Volume روی
> `/data` بگذار، یا بعد از اضافه‌کردنِ کانال‌ها یک بار **💾 بکاپِ کانال‌ها** بزن و خطش را
> در `COPY_CHANNEL_ID` ذخیره کن (این متغیر همیشه می‌ماند و دستی‌کاری لازم نیست).
> اگر خواستی بدونِ پرسیدن و خودکار به اولین کانال برود: `COPY_CHANNEL_ASK=0`.
> اگر `CHANNEL_AUTOSYNC=1` بگذاری، هر کانالی که داخلِ ربات اضافه/حذف شد خودش در
> `COPY_CHANNEL_ID` هم نوشته می‌شود (نیاز به `RAILWAY_API_TOKEN` و آیدی‌های پروژه).

### ۴) کوکی‌ها — برای یوتیوب و اینستاگرام لازم است

بدون کوکی، یوتیوب خطای «Sign in to confirm you're not a bot» می‌دهد یا کیفیت را کم می‌کند.
سه راه داری (هر کدام را خواستی):

| راه | متغیر | توضیح |
|---|---|---|
| محتوای کوکی در متغیر | `COOKIES_CONTENT` | کل متن فایل کوکی (Netscape). چندخطی هم می‌شود |
| همان، فقط یوتیوب | `YOUTUBE_COOKIES_CONTENT` | بر `COOKIES_CONTENT` اولویت دارد |
| محتوای base64 | `COOKIES_CONTENT=base64:…` | اگر Railway با خط جدید مشکل داشت |
| آدرس اینترنتی | `COOKIE_URL` / `YOUTUBE_COOKIE_URL` | یک لینک به فایل `.txt` کوکی (مثلاً GitHub raw) |
| فرستادن از تلگرام | — | فایل کوکی را برای ربات بفرست (دستور `/cookie`)؛ در Volume می‌ماند |

**چطور فایل کوکی یوتیوب بگیرم؟** با افزونهٔ «Get cookies.txt LOCALLY» در مرورگر، در حالت لاگین‌شده به یوتیوب برو و فایل را ذخیره کن، بعد محتوایش را در `COOKIES_CONTENT` بگذار.
اگر چند کوکی داری: `YOUTUBE_COOKIE_URL_1` تا `YOUTUBE_COOKIE_URL_10` (ربات خودش یکی‌یکی امتحان می‌کند) و `YOUTUBE_COOKIE_ORDER` = `round_robin` یا `random`.
کوکی‌های سایت‌های دیگر: `INSTAGRAM_COOKIE_URL`, `TIKTOK_COOKIE_URL`, `TWITTER_COOKIE_URL`, `VK_COOKIE_URL`.

### ۵) یوتیوب: PO Token (توصیه‌شده)

| متغیر | توضیح |
|---|---|
| `YOUTUBE_POT_ENABLED` | `true` = روشن (پیش‌فرض `false`). کیفیت ۷۲۰p+ و پایداری بیشتر، حدود ۳۰۰ مگ رم بیشتر |
| `YOUTUBE_POT_BASE_URL` | پیش‌فرض `http://127.0.0.1:4416` (provider داخل همین سرویس بالا می‌آید) |
| `YOUTUBE_POT_DISABLE_INNERTUBE` | اگر توکن‌ها کار نکرد، `true` کن |

> اگر پلنت رم کم دارد (زیر ۱ گیگ)، `YOUTUBE_POT_ENABLED=false` بگذار و به کوکی بسنده کن.

### ۶) پروکسی (اختیاری)

| متغیر | توضیح |
|---|---|
| `PROXY_TYPE` | `http` / `https` / `socks4` / `socks5` / `socks5h` |
| `PROXY_IP` / `PROXY_PORT` | آدرس و پورت پروکسی |
| `PROXY_USER` / `PROXY_PASSWORD` | اگر پروکسی یوزر/پس دارد |
| `PROXY_2_*` | پروکسی دوم، با همان الگو |
| `PROXY_SELECT` | `round_robin` یا `random` |

### ۷) منابع و محدودیت‌ها (برای پلن‌های کوچک مهم است)

| متغیر | پیش‌فرض روی Railway | توضیح |
|---|---|---|
| `MAX_FILE_SIZE_GB` | `2` | حداکثر حجم هر فایل |
| `MAX_CONCURRENT_DOWNLOADS` | `2` | دانلود همزمان هر کاربر |
| `MAX_CONCURRENT_UPLOADS` | `2` | آپلود همزمان به تلگرام |
| `TG_YTDLP_BG_WORKERS` | `8` | تعداد ورکر پس‌زمینه |
| `MAX_VIDEO_DURATION` | `43200` | حداکثر طول ویدیو (ثانیه) |
| `MAX_PLAYLIST_COUNT` | `50` | حداکثر تعداد آیتم پلی‌لیست |
| `MAX_SUB_QUALITY` | `720` | کیفیت حداکثر زیرنویس |
| `DOWNLOAD_TIMEOUT` | `7200` | مهلت هر دانلود (ثانیه) |
| `RATE_LIMIT_PER_MINUTE` / `_HOUR` / `_DAY` | `5` / `60` / `1000` | محدودیت درخواست هر کاربر |
| `TURN_OFF_LIMITS_FOR_ADMINS` | `true` | ادمین‌ها محدودیت نداشته باشند |

### ۸) دیتابیس (پیش‌فرض: لوکال روی Volume)

| متغیر | توضیح |
|---|---|
| `USE_FIREBASE` | `false` = دیتابیس لوکال (پیشنهادی روی Railway). `true` = فایربیس |
| `FIREBASE_CONF` | JSON کانفیگ فایربیس (یک‌خطی) |
| `FIREBASE_SERVICE_ACCOUNT` | مسیر فایل سرویس‌اکانت (مثلاً `/data/service-account.json`) |

### ۹) زیرساخت (کم‌تر لازم می‌شود)

| متغیر | توضیح |
|---|---|
| `DATA_DIR` | مسیر دادهٔ پایدار — همان مسیر Volume (`/data`)؛ دست نزن |
| `PORT` / `HEALTH_PORT` | Railway خودش `PORT` می‌دهد؛ سرور سلامت روی همان بالا می‌آید |
| `HEALTH_STRICT` | `true` = `/ready` وقتی ربات خواب باشد `503` بدهد |

## 💾 ذخیره‌سازی و اندازهٔ پلن

* **Volume روی `/data` بگذار** — همهٔ دادهٔ مهم (کاربران، کوکی، کش، سشن) آنجا می‌رود.
* کاربران و کوکی‌ها + فایل‌های در حال دانلود روی همین دیسک‌اند؛ اگر حجم دانلود زیاد است، Volume بزرگ‌تر بگیر (وگرنه وسط دانلود دیسک پر می‌شود).
* پیشنهاد پلن: **رم ۱ گیگ** برای استفادهٔ معمولی کافی است (بدون PO Token)؛ برای یوتیوب سنگین/چند دانلود همزمان ۲ گیگ بهتر است.
* رم و CPU به‌طور خودکار از cgroup کانتینر خوانده می‌شود و تعداد ورکر/آپلود متناسب تنظیم می‌شود.

## 🧰 عیب‌یابی

| مشکل | راه‌حل |
|---|---|
| `❌ این متغیرها ست نشده‌اند: …` | متغیرها را در Variables اضافه کن و Deploy بزن |
| بیلد خطا می‌دهد | Deploy Logs را ببین؛ اگر خطای شبکه بود، دوباره Deploy کن (بیلد اول طولانی است) |
| ربات جواب نمی‌دهد | لاگ را ببین؛ اگر `bot.log` خطا دارد، `VERBOSE_LOGGING=true` بگذار |
| یوتیوب «ربات هستی» یا کیفیت پایین می‌دهد | کوکی بده (`COOKIES_CONTENT`) و `YOUTUBE_POT_ENABLED=true` کن |
| کوکی‌ها با هر دیپلوی پاک می‌شوند | Volume را روی `/data` وصل نکرده‌ای |
| ارسال لاگ به کانال خطا می‌دهد | ربات را در کانال‌های `LOGS_ID`/`LOG_EXCEPTION` ادمین کن |
| `Killed` / ری‌استارت پشت‌سرهم | رم کم است: `MAX_FILE_SIZE_GB` و `MAX_CONCURRENT_DOWNLOADS` را کم کن و `YOUTUBE_POT_ENABLED=false` بگذار |
| دیسک پر می‌شود | Volume بزرگ‌تر، یا `MAX_FILE_SIZE_GB` را کم کن |
| بعد از دیپلوی همه‌چیز ریست شد | Volume روی `/data` → Mount path درست ست نشده |

## 🔄 آپدیت

* **سورس:** تغییرات این ریپو را Pull/Merge کن (یا Fork خودت را از مخزن اصلی آپدیت کن) → Railway خودش دیپلوی می‌کند.
